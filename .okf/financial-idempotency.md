# Financial Idempotency

- **Financial HTTP idempotency is not output cache.** It needs a trusted stable `CallerScope`. `AdditionalHeaders` defaults empty. Stores return immediate `InFlight`. Status mapping follows the IETF Idempotency-Key draft: in-flight `409` + `Retry-After`, payload mismatch `422`, unreplayable `409` without `Retry-After` (a 5xx or `Retry-After` there invites automatic retries that re-run the handler once retention expires). These three also set a `FinancialIdempotencyErrorCodes` value as `ValidationFailure.ErrorCode` (public contract; the default `ErrorResponse` drops it, `ProblemDetails` shows it only with `IndicateErrorCode`). Broken store contracts stay `500` with their own messages. Settlement is ownership-token CAS. Active reservations never auto-expire. Completed and unreplayable retention start at settlement. The middleware passes max(`UnreplayableRetention`, `Duration`) to `MarkUnreplayableAsync`, so an uncertain outcome is never forgotten before a completed one would be. A second `AddFinancialIdempotency()` throws.
- **Financial abandon vs retain:** only `RejectFinancialIdempotencyWithoutSideEffects` releases a key. `FeRequestHandler` uses it for its pre-endpoint `415` and hit-counter `403`/`429`. Exceptions, cancellation during the handler, ambiguous non-2xx, and endpoint validation failures retain the key. A finished 2xx completes even if the client already aborted. `Started` without a token, or `Replay` without a response, fails closed and does not run the handler.
- **Financial completion confirmation:** successful first-response delivery accepts only `CompleteAsync` returning `Applied`. `AlreadySettled` includes completed and unreplayable states, so it fails closed. Cleanup must preserve completed snapshots after an ambiguous or lost completion acknowledgement; retries replay them. `FinancialIdempotencyFaultTests` covers both terminal states and ownership loss.
- **Financial `PipelineKey` is per request.** `ExecAsync` requires `FinancialIdempotencyMiddleware.PipelineKey` for that invocation, including direct callers such as agent invocation. The middleware sets it only around the reserved `next()` and clears it in `finally`.
- **Financial response callbacks:** `AddFinancialIdempotency` inserts `FinancialResponseStartupFilter` first among registered startup filters. Its `FinancialResponseFeature` collects application `OnStarting` registrations. Capture transfers pending callbacks in registration order, so upstream and downstream callbacks execute LIFO before settlement, once each. Callback failures retain uncertainty; completed settlement still precedes transport start. Callbacks must use the current `HttpContext.Response`; cached response features and response-feature replacement remain unsupported. Cached header dictionaries bypass sealing after capture starts.
- **Financial cookies:** capture shares the original header dictionary until `StartAsync` finishes its callbacks, then seals a separate read-only copy. This preserves append/delete through cookie features initialized upstream, including cookie policy, while keeping first-response cookies out of replay snapshots. Cookie mutations must finish before capture starts.
- **Financial payload/snapshot safety:** hashing must rewind/restore the request body and clear rented buffers. Snapshots copy headers; exclusions are stricter than replay filtering and leave the first response intact. `FinancialIdempotencyResponse` holds `ImmutableArray`s, so stores keep and replay the received instance without cloning. Only `ImmutableCollectionsMarshal.AsImmutableArray` wraps without copying; use it only on buffers nothing writes afterwards (the middleware's body snapshot). Replay gives live response headers their own arrays; never assign a stored array straight into `HttpResponse.Headers`.
- **Financial identity bytes are a persistence contract** (version-1 payload includes media type and declared charset). PathBase is included. One trailing slash is normalized (empty root becomes `/`). Repeated or internal slashes and the case option stay. Only RFC 3986 default ports are stripped. Changing these identities after release requires migration or draining reservations, never a mixed-version rollout.
- **Financial memory store:** expire a completed or unreplayable key on that key's `TryBegin`. Reclamation is requested when admitting at `maxEntries` or on complete, but skips scanning before the earliest terminal deadline. The deadline is a conservative lower bound under the store lock; direct key removal may leave it stale (extra scans, never extended retention). Keep the due scan in its separate helper to preserve expiry-heavy performance. Capture includes empty 204 and pending pipe bytes. Overflow fails closed. File contents are hashed. Process restart drops protection. Durable reconciliation and downstream business idempotency stay app-owned.
