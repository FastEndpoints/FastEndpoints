# Generated Code

## Roslyn generators (`Src/Generator`)
The package ships under `analyzers/dotnet/cs`, with `DevelopmentDependency=false`. Consume it as an analyzer (see the project-reference example below).

| Generator | Purpose |
| --- | --- |
| `DiscoveredTypesGenerator` | Emits discovered endpoint/handler/validator/etc. type lists (`DiscoveredTypes`) for AOT-friendly `AddFastEndpoints` |
| `AccessControlGenerator` | Permission constants/groups from `AccessControl(...)` calls (bare, `this.` or `base.`; calls binding to a non-`FastEndpoints` method are skipped, unresolved ones kept); category args resolve as string literals or compile-time string constants (`const`, `nameof`, etc.) via semantic model. Permission codes come only from `Src/Generator/AclHash.cs`, which the library compiles by link (`BaseEndpoint.GetAclHash` delegates to it), so compile-time `Allow.*` codes match runtime `AccessControl(...)` hashes. Keep it self-contained (BCL only, netstandard2.0-compatible) and never change its output, since users persist codes. Endpoint permissions and hand-written partial properties both go through `AclHash.Compute`, so a partial property's code equals the `AccessControl(...)` code for the same name; distinct permission names colliding on a 3-char hash fail compilation with `FEAC001`. Hand-written `Allow` lookups cover every public `const`/`static` `System.String` field and partial string property in any partial part, minus `[HideFromDocs]` (the pre-v8.2 reflection contract, narrowed to strings): select per declarator and check the type and `static` semantically, since parts may omit `static` and spell the type `String` |
| `ReflectionGenerator` | Reflection cache support for reduced runtime reflection |
| `ServiceRegistrationGenerator` | DI registration from attributes. Registrations are sorted by lifetime, service type, then implementation type, so which duplicate registration wins in DI (the last one) never depends on source file order |
| `GenericProcessorTypesGenerator` | Generic pre/post processor type materialization |

The discovery whitelist is owned by `DiscoveredTypesGenerator`; check it when adding a discoverable contract. Its entries are exact metadata names, so list each generic arity (``FastEndpoints.ICommandHandler`1``).

Interface and attribute checks go through `Extensions.MetadataFullName()` (`ImplementsInterface()`, `HasAttribute()`, `AttributeData.Matches()`): namespace-qualified and arity-aware, mirroring the runtime's exact `Type` checks. Don't match by simple name or display-string prefix, which picks up lookalikes (`IEndpointFactory` for `IEndpoint`, a user's `MyApp.DontRegisterAttribute`) that reflection discovery ignores.

Type-discovering generators share `Extensions.IsCandidateTypeDeclaration()` (class or record with a base list, not nested in an open generic) and `IsRegistrable()` (mirrors `AssemblyScanner.IsTypeMatch`: not abstract, no `[DontRegister]`); change the rule there. They skip open generic classes and non-generic classes nested inside an open generic (`IsNestedInGenericType()`): nested types inside open generics are generic at runtime (`Type.IsGenericType`), `AssemblyScanner` drops them, and emitting `Outer<T>.Inner` does not compile. `ReflectionGenerator` additionally requires class declarations (endpoints are classes). `GenericProcessorTypesGenerator` still matches open-generic processors while skipping open-generic endpoints; `AccessControlGenerator` inspects `AccessControl(...)` calls directly.

Incremental pipeline rules (all generators):
- No generator instance state. The root namespace comes from `RootNamespaceProvider()` (or a `CompilationProvider.Select`) combined into the output step, never from a field set in a transform.
- Transform results must be value-equal and hold no `ISymbol`/`SyntaxNode`: use records of strings, with `EquatableArray<T>` for collections. A partial comparer (span length, display name only) leaves stale output in the IDE; command-line builds won't show it, so cover it with a reused-driver test.
- Emit type names via `ToFullName()` (`global::`-qualified) and property names via `EscapeKeyword()`, because generated files live in `namespace {AssemblyName}` and user namespaces/types can shadow unqualified names.
- Endpoint DTO types come from `GetEndpointBase()` (`FastEndpoints.Endpoint<TRequest, TResponse>`), not the immediate base type; `EndpointWithoutRequest*` resolves to `EmptyRequest`.

`ReflectionGenerator` derives registration namespaces from the assembly name, not endpoint namespaces. When `FastEndpoints.ReflectionCache` is available, it emits `ReflectionData.g.cs` even without non-generic classes. Messaging-only compilations without that HTTP contract emit no reflection registration. Each endpoint is walked with its own collected-type set (request DTO graph first, endpoint class last, via `TypeCollector.CollectEndpoint`); `Generate` merges models by type name (first wins), so a DTO's model must not depend on which endpoint reached it. Property and constructor selection mirror the runtime binder (`BinderExtensions`): most-derived property per name (emitted as `GetProperty(nameof(...), typeof(T))`, because a name-only lookup throws `AmbiguousMatchException` when a `new` property changes the type; `T` is a file-level `using pN`/`tN` alias shared with the setter cast, stripped of the top-level nullable annotation, which aliases and `typeof` reject, but keeping nested ones, whose absence makes the cast warn CS8619; a top-level `dynamic` is emitted as `object` and `dynamic` is never collected as a DTO, because `typeof(dynamic)` fails with CS1962 even through an alias, while nested `dynamic` such as `List<dynamic>` compiles; runtime `BindableProps()` returns both such properties and the top-level `RequestBinder` then fails with a duplicate key, a known open divergence), attributes inherited through `OverriddenProperty`, only `JsonIgnoreCondition.Always` excluded, fewest-parameter public constructor with optional and `params` arguments omitted (`ObjectFactory` is skipped for `abstract`, `partial`, zero-property, endpoint property-injection, or no-public-ctor types). `GenericProcessorTypesGenerator` closes post-processors only with each endpoint's own request/response pair, matching `EndpointDefinition`'s `MakeGenericType`, and skips DTOs that fail the processor's `class`/`struct`/`unmanaged`/`new()`/type constraints (checked by fully qualified name; constraint types referencing the processor's own type parameters, like `IResult<TRequest>`, are stored as `{ordinal}` templates and closed with the endpoint's DTOs, since an unsatisfied constraint emits code that fails with CS0311; `new()` also rejects DTOs with `required` members unless the public parameterless constructor carries `[SetsRequiredMembers]`; these required-member rules live in `Extensions` and are shared with `ReflectionGenerator`'s `ObjectFactory` emission, so change them there). It always emits `GenericProcessorTypes.All`, empty without open generic processors, because apps pass it to `AddFastEndpoints` unconditionally (FE-Docs Native AOT page). Generated bodies keep `using` directives above the namespace so `{root}.System`-style namespaces cannot shadow them, and non-ACL generators also `global::`-qualify framework names (`AccessControlGenerator` emits unqualified framework types in `Allow`). Regressions: `Tests/UnitTests/FastEndpoints/*GeneratorTests.cs`; native parity via NativeAotChecker's `ReflectionParityEndpoint` (overrides, nested `new` property of a different type, `[JsonIgnore]` conditions) and `RecordEventHandlerEndpoint` (record discovery).

## MSBuild / CLI generation
- **`FastEndpoints.Generator.targets`:** when `GenerateSerializerContexts=true` (optional `SerializerContextOutputPath`, default `Generated/FastEndpoints`, and `GeneratorCliVersion`), runs Generator.Cli to emit STJ serializer contexts.
- **CLI type index:** `SourceFileWalker` records class, struct, record, and enum declarations so generic type arguments (including enum dictionary keys) emit fully qualified `typeof(...)` in `[JsonSerializable]`. The same single parse pass records endpoint classes (`EndpointDeclaration`, file then document order); do not re-walk syntax trees for discovery. Cache schema `v4` invalidates older `.fastendpoints-generator-cache` files; bump it whenever resolution results change for unchanged inputs. The cache also stores the root namespace, so an assembly name change regenerates. Zero serializable types still writes both files (comment-only context, no-op `AddSerializerContextsFrom*()`): STJ rejects a context without `[JsonSerializable]`, and output from an earlier run must not survive.
- **CLI external fallback:** unresolved capitalized names lazily load referenced-project sources, then NuGet metadata (prefetched in parallel on the first fallback). `AnalysisContext.ResolveType` owns lookup, fallback order, loader laziness, and prefetch; `NuGetPackagesInspected` must mean "loader consulted", not "prefetch started" (prefetch warnings surface only when consulted, and `Main` flushes diagnostics in `finally`). Because `*Inspected` flags force later cache checks to hash those inputs, `IsExternalFallbackCandidate` excludes `GeneratorConfig.WellKnownExternalTypes` (unqualified names only, so only add unambiguous BCL/framework names; qualified/alias-expanded names still fall back) and skipped names (`GeneratorConfig.IsSkippedNamespace` / `IsSkippedTypeName` own the `SkipNamespaces` / `SkipTypes` policy for both emission and fallback). `BuiltInCollectionTypes` blocks generic roots only, since non-generic `Queue` may be a user DTO. Generic lookups use ``Name`arity`` in every index (strip existing arity from NuGet display names before re-appending). `Program.Cache.cs` (`IsUpToDate`, `CreateCacheState`) reads lazy input hashes only when the matching `*Inspected` flag is true (or a skipped scan runs), and writes the cache after both generated files.
- **CLI namespace contract:** the targets pass `--assembly-name $(AssemblyName)` (standalone fallback: project file name). The CLI namespace and `AddSerializerContextsFrom*` suffix must use the same rules as the Roslyn generators. Those rules live only in `Src/Generator/NamespaceExtensions.cs`, which the CLI compiles by link (`ToValidNameSpace()` keeps dots and prefixes `_` to empty, digit-leading or keyword segments; `ToValidIdentifier(string.Empty)` strips all non-alphanumerics for method suffixes). Keep that file self-contained (BCL plus `Microsoft.CodeAnalysis.CSharp`, netstandard2.0-compatible), and don't re-add naming helpers to the CLI. `<RootNamespace>` is ignored on both sides. Divergence makes one `using` insufficient and breaks AOT setup for dotted names.
- **OpenApi targets:** `ExportOpenApiArtifactsBeforeAotPublish` exports `.json`/`.http` when `ExportOpenApiDocs`/`ExportHttpFiles` set (aliases keep old target names). Single JIT intermediate dir + combined CLI flags when both enabled; app one-call export orchestrator (`ExportOpenApiArtifactsAndExitAsync`, or either legacy `Export*AndExitAsync` alias) reads those flags (see NativeAotChecker).
- Dev mode uses `Src/Generator.Cli/bin/$(Configuration)/net10.0/FastEndpoints.Generator.Cli.dll`; `BuildFastEndpointsGeneratorCli` automatically builds a missing DLL before `CoreCompile` when serializer generation is enabled. Package mode installs/updates the local tool `FastEndpoints.Generator.Cli`, pinned to the package folder name (`.../<version>/build/..`; the CLI shares the library `<Version>`). An empty `GeneratorCliVersion` means a tool install and `--prerelease` update on every build, so keep that extraction working. Update passes `--allow-downgrade` when pinned, because a manifest from older targets may hold a newer prerelease; without it install and update both fail on every build. The `obj/` sentinel (`fastendpoints-tool.version`) is written only when install or update succeeds; an unconditional write would make a failed first install permanent, since later builds skip the install and `dotnet clean` doesn't remove it.
- NativeAotChecker isolates serializer contexts in `obj/$(Configuration)/$(TargetFramework)/SerializerCtx` and includes them after generation, including on a clean build. Do not include its old `Generated/` sources. Checker fixture native binary isolation (overriding `AppFixture.Aot`'s default `bin/aot` path): [testing.md](testing.md#commands).

## Do not hand-edit
- Compiler-generated outputs under consumer `Generated/` folders
- NativeAotChecker `Generated/`, `wwwroot/openapi/`, publish `aot/` (gitignored)
- Packaged analyzer binary contents

Prefer changing **generator sources** under `Src/Generator/*.cs` or **targets**, then rebuild.
