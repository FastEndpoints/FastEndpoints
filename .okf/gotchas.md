# Gotchas

## Accepted policies and review exclusions

- **Poison-event disposal is an accepted reliability policy (owner decision, 2026-10-03):** ordinary and ACK hub dispatchers complete/discard an unreadable event after three deserialization failures, including when `OnDeserializeEventError<TEvent>` is absent or throws (for example, a DLQ write fails). A throwing callback is logged; the completed source row becomes eligible for normal purging. Recovery/DLQ persistence is consumer-owned and best-effort. Future bug hunts should exclude this completion-after-failed-recovery behavior as a bug or improvement finding. Preserve this policy unless the owner explicitly requests a contract change. Cancellation still leaves durable rows pending. Sources: `HubContext.DeserializeEvent`, `EventHubExceptionReceiver.OnDeserializeEventError`, and `EventQueueTests.Deserialization.cs` (`event_deserialization_terminal_failure_notifies_before_completion_and_continues`, including throwing-receiver variants).
- **ACK inbox execution expiry starts at each insertion attempt:** the receiver refreshes `ExpireOn` immediately before each `StoreEventAsync` call. Failed attempts leave the next attempt a fresh execution window. A single successful call exceeding that window can still persist an expired row and be acknowledged. **Accepted review exclusion (owner decision, 2026-10-02):** future bug hunts should skip this slow-successful-insert expiry boundary as a bug or improvement finding. The accepted outcome is hub completion with an expired inbox row and zero handler executions. Preserve attempt-time expiry unless the owner explicitly requests a contract change. Coverage: `EventQueueTests.AckStoreExpiry.cs`, `delivery_ack_successful_store_longer_than_execution_window_remains_expired`. Duplicate detection preserves persisted expiry, completion, and retention, including a commit whose response was lost. Ordinary subscribers keep their existing expiry timing.

## Operational gotchas

- **Generation contracts:** analyzer packaging, open-generic discovery exclusions, reflection namespaces, access-control constants, serializer CLI setup, and generated outputs: [generated-code.md](generated-code.md).
- **AOT discovery:** reflection `AddFastEndpoints()` is not supported under AOT. Use `AddFastEndpoints(DiscoveredTypes.All)` plus the Generator analyzer.
- **Pinned packages:** do not casually bump `Microsoft.CodeAnalysis.CSharp` or `Microsoft.OpenApi.Kiota.Builder`. Why: [dependencies.md](dependencies.md).
- **NuGet duplicate versions:** use `--skip-duplicate` when pushing solution packages. Independently versioned Agents may already be published. Release commands: [workflows.md](workflows.md#pack-and-publish).
- **User DotSettings:** `*.sln.DotSettings.user` is personal. Not repo policy.

### Agents compatibility

- **MCP refusal auditing:** `OnToolCallRefused` is call-path-only, not a side effect of `ToolVisibilityFilter` or listing. Report once only after no visible name candidate resolves, or at the invocation recheck. Hidden duplicates must not audit a successful call to a visible candidate. Keep the capturing audit helper separate from the callback-null fast path. Configure auditing before resolution, not inside the visibility filter; the invocation recheck reads the current callback separately. Contract and usage: `../FE-Docs/src/content/docs/27-ai-agents.md`.
- **MCP schema descriptions:** `JsonSchemaBuilder` applies `DescriptionAttribute` to input/output properties while preserving JSON names and nested schemas. Source-generated metadata lacks `AttributeProvider`, so resolve the public property through `JsonPropertyInfo.DeclaringType` and its serialized name. Omit empty descriptions; convert boolean schemas to equivalent object schemas before annotation. Tests: `JsonSchemaBuilderTests`, `McpToolSchemaRootTests`.
- **Agents versioning:** `Src/Agents/Directory.Build.props` must `Import` the parent props. MSBuild stops at the first `Directory.Build.props`. Shared agent code is linked compile, not a NuGet.
- **Agents friend-assembly binary contract:** `InternalsVisibleTo` in `Src/Library/Metadata.cs` for `FastEndpoints.Mcp` and `FastEndpoints.A2A` (independent versions). Recompiling addons here does not prove published NuGets still load. Changing the name, arity, parameter types, or return type of a stocked internal can `MissingMethodException` shipped addons. Touch any of these in Library: check the agent packages and restock this list in the same change.
  - **Reflection / binding** (`BinderExtensions.cs`, `ReflectionExtensions.cs`): `Type.BindableProps()` (return type is part of the CLR signature), `PropertyInfo.FieldName()`, `Type.IsComplexType()`, `Type.IsCollection()`.
  - **Bootstrap / discovery** (`EndpointBootstrap.cs`, `EndpointData.cs`, `MainExtensions.cs`): `EndpointBootstrap.CreateEndpoint(HttpContext, EndpointDefinition)`, `EndpointData.Found`, `MainExtensions.BuildRoute(StringBuilder, int, string, string?)`. Do not add a `BuildRoute` parameter. `DontVersion()` is how version 0 omits the segment.
  - **EndpointDefinition fields:** `SerializerContext`, `Disposable`, `DisposableAsync`.
  - **Config / type tokens:** `Config.SerOpts` (also `using static FastEndpoints.Config`), and `Types` fields agents use: `EmptyRequest`, `FromBodyAttribute`, `ToHeaderAttribute`, `String`.
  - **Call sites to check when restocking:** `Src/Agents/Shared/` (`AgentRequestBuilder.cs`, `AgentJsonPropertyNames.cs`, `AgentHttpContextFactory.cs`, `EndpointInvoker.cs`, `AgentEndpointCatalog.cs`), `Src/Agents/Mcp/` (`McpToolSchemaFactory.cs`, `EndpointMcpToolSource.cs`), `Src/Agents/A2A/` (`A2AJsonRpcEndpoint.cs`, `A2ASkillDispatcher.cs`, `Extensions.cs`).

### HTTP and binding

- **OpenAPI changes:** read [openapi.md](openapi.md) for generation ownership, schema isolation, validation, examples, tags, and compatibility. Regression map: [testing.md](testing.md#openapi-regression-map).
- **Enum binding:** default `AllowUndefinedEnumValues=false` rejects undefined numerics and comma/repeated-name lists for non-flags enums (`Enum.TryParse` ORs names into potentially valid members). Defined `[Flags]` combinations still bind; `true` restores raw `TryParse`. JSON bodies follow STJ options.
- **Validation hot path:** keep `Endpoint.HandleValidationFailure(req, ranPreProcessors, ct)` private and separate from `ExecAsync`. An async local introduces per-request closure allocation. `ValidationFailed` is already a public property.
- **DataAnnotations service scope:** pass the endpoint's `HttpContext.RequestServices` explicitly through `ValidateRequest` and recursive validation. Each object's `ValidationContext` must use that provider, not the global resolver or an ambient context, so custom attributes share the endpoint's scoped services. Keep the recursive helper static to avoid captured state.
- **`ResponseCacheExecutor` caches `Cache-Control` once per endpoint.** That is valid only because `ResponseCache(...)` is `ThrowIfLocked()`. A runtime mutation of location or duration must invalidate the cached string.
- **Multi-route mapping:** `EndpointRouteMapper` clears `AttribsToForward` and locks the definition after the route loop. Moving either inside loses attribute metadata or locks on the first route. `EndpointExtensions.Initialize` populates forwarded attributes only for attribute-configured endpoints.
- **`DontVersion()` vs `Version(0)`:** `Version(0)` is still unset. `EpVersion.Init()` then applies `DefaultVersion`. `DontVersion()` keeps version 0 and omits the route segment. Do not use `-1` or any negative sentinel. OpenAPI release-group filtering is `version >= MinEndpointVersion && version <= MaxEndpointVersion`, and `Current` is public metadata.
- **Handler short-circuit is opt-in.** Pre-processors skip the handler when `ResponseStarted` is true. `OnBeforeHandle*` does not, unless `DontExecuteHandlerIfResponseStarted()` set `SkipHandlerIfResponseStarted`. That early return also skips `OnAfterHandle*`. Post-processors still run.

### Testing and service lifetimes

- **WAF cache:** one cached factory per `AppFixture` type. Static state on that factory leaks across tests. Register doubles in `ConfigureServices`. Teardown hook: [testing.md](testing.md).
- **Test url cache route is opt-in:** `EndpointRouteMapper` maps anonymous `_test_url_cache_` (every route and endpoint type name) only when `IConfiguration["FastEndpoints:ExposeTestUrlCache"]` is `true`. Do not map it unconditionally or gate it on environment name. In-process WAF uses the always-on `IEndpoint.SetTestUrl` cache. Out-of-process routeless helpers fall back to the route (`HttpClientExtensions.GetTestUrlFor` when `IEndpoint.TestURLFor` misses). `AppFixture.Aot` sets `FastEndpoints__ExposeTestUrlCache=true`.
- **Routeless test URL encoding:** `GetTestUrlFor()` encodes matched route values with `Uri.EscapeDataString`. Unmatched placeholders stay intact. Query values use `WebUtility.UrlEncode`. Do not use query encoding for path segments (`+` is not a path-space escape).
- **JWT revocation:** check the header on requests without a selected endpoint, and check saved `access_token` from selected JWT schemes’ cached `AuthenticateAsync` results only when an endpoint is selected. Combine endpoint `IAuthorizeData` and direct `AuthorizationPolicy` metadata with the policy provider (including default/fallback policies); use the default authenticate scheme when the effective policy names no schemes. Cookie-only routes must leave unrelated JWT handlers untouched. Register after `UseRouting()` and before authentication for query/cookie tokens; an optional early registration is header-only. Early authentication caches empty results from endpoint-gated `OnMessageReceived` extraction. Saved tokens require `SaveToken=true` (helper default). `IAllowAnonymous` skips all checks. `JwtRevocationMiddlewareTests` covers endpoint-gated query/cookie extraction across early and routed checks, valid/revoked tokens, downstream authentication, and one validation per request.
- **Singleton construction:** `ServiceResolver.CreateSingleton` resolves the host’s `IServiceResolver` from request services, then constructs from its root provider. This covers validators, mappers, processors, binders, feature flags, event handlers, and executors. Constructing from request services leaks scope; the captured provider may belong to a disposed host in multi-host tests. `Factory.AddTestServices` is the empty-root exception.
- **Remote event protocols and isolation:** provider-wide opt-in, inbox dedupe/signaling, replay retention, deadlines, and static storage isolation are owned by [remote-events.md](remote-events.md). Check it before changing event queues or hosting a second hub.
- **Host-test statics:** `UseFastEndpoints()` / `MapFastEndpoints()` sets `ServiceResolver.Instance` and, on the first call, replaces `Config.SerOpts.Options` (`MainExtensions.SerializerConfigured`). It also assigns `ValidatorOptions.Global.PropertyNameResolver` on every call. Restore those before the test returns. Unit tests that mutate them join `[Collection(RouteMapperCollection.Name)]` and follow the `IDisposable` reset in `EndpointRouteMapperTests` (also `RoutePrefixTests`, `WarmupTests`, `FinancialIdempotencyMapperTests`). OpenAPI host setup: [testing.md](testing.md#openapi-self-hosted-isolation).
- **Test receivers are append-only spies.** Match rules and capture timing: [testing.md](testing.md).

### Remote RPC and reflection

- **RPC wire format is per-connection and set-once:** set `RemoteConnection.MarshallerFactory` before any `Register<>()` (registration captures it and throws otherwise). Server and client must match. Both take the bound gRPC method name from the factory (MessagePack `""`, protobuf `Execute`). The default comes from DI, so `AddHandlerServer(marshaller:)` also becomes the default outbound factory in a process that is both server and client. Set it per connection when the peer uses a different format.
- **Reflection needs protobuf:** `MapHandlerReflection()` throws at startup unless `AddHandlerServer(marshaller: new ProtobufMarshallerFactory())` is set. `AddHandlerReflection()` only registers services. MessagePack has no descriptors. Attribute-free field numbers are positional, so adding or renaming a property renumbers the rest. Pin with `[ProtoContract]` / `[ProtoMember(n)]` when the contract must survive edits.
- **Reflection describes less than it serializes:** the descriptor generator skips `DateTime`, `DateOnly`, `TimeOnly`, `TimeSpan`, `decimal`, `Guid`, `Uri`, dictionaries, and nested commands (`CommandNotDescribable`). Those handlers still run via protobuf-net. Only field numbering is shared with the marshaller. `IsMessage(KeyValuePair<,>)` stays false so map entries are not published as empty messages.
- **Protobuf BCL denylist:** `ProtobufMarshallerFactory.IsMessage` / `IsNonMessageType` keep BCL specials out of attribute-free `Model.Add` (hollow contracts corrupt the wire). Edit that denylist together with the descriptor tests. Do not copy the type list into OKF.

### Financial idempotency

- **Financial HTTP idempotency is not output cache.** It needs a trusted stable `CallerScope`. `AdditionalHeaders` defaults empty. Stores return immediate `InFlight` (`409`). Settlement is ownership-token CAS. Active and uncertain reservations never auto-expire. Completed retention starts at completion. A second `AddFinancialIdempotency()` throws.
- **Financial abandon vs retain:** only `RejectFinancialIdempotencyWithoutSideEffects` releases a key. `FeRequestHandler` uses it for its pre-endpoint `415` and hit-counter `403`/`429`. Exceptions, cancellation during the handler, ambiguous non-2xx, and endpoint validation failures retain the key. A finished 2xx completes even if the client already aborted. `Started` without a token, or `Replay` without a response, fails closed and does not run the handler.
- **Financial completion confirmation:** successful first-response delivery accepts only `CompleteAsync` returning `Applied`. `AlreadySettled` includes completed and unreplayable states, so it fails closed. Cleanup must preserve completed snapshots after an ambiguous or lost completion acknowledgement; retries replay them. `FinancialIdempotencyFaultTests` covers both terminal states and ownership loss.
- **Financial `PipelineKey` is per request.** `ExecAsync` requires `FinancialIdempotencyMiddleware.PipelineKey` for that invocation, including direct callers such as agent invocation. The middleware sets it only around the reserved `next()` and clears it in `finally`.
- **Financial response callbacks:** `AddFinancialIdempotency` inserts `FinancialResponseStartupFilter` first among registered startup filters. Its `FinancialResponseFeature` collects application `OnStarting` registrations. Capture transfers pending callbacks in registration order, so upstream and downstream callbacks execute LIFO before settlement, once each. Callback failures retain uncertainty; completed settlement still precedes transport start. Callbacks must use the current `HttpContext.Response`; cached response features and response-feature replacement remain unsupported. Cached header dictionaries bypass sealing after capture starts.
- **Financial cookies:** capture shares the original header dictionary until `StartAsync` finishes its callbacks, then seals a separate read-only copy. This preserves append/delete through cookie features initialized upstream, including cookie policy, while keeping first-response cookies out of replay snapshots. Cookie mutations must finish before capture starts.
- **Financial payload/snapshot safety:** hashing must rewind/restore the request body and clear rented buffers. Snapshots copy headers; exclusions are stricter than replay filtering and leave the first response intact.
- **Financial identity bytes are a persistence contract** (version-1 payload includes media type and declared charset). PathBase is included. One trailing slash is normalized (empty root becomes `/`). Repeated or internal slashes and the case option stay. Only RFC 3986 default ports are stripped. Changing these identities after release requires migration or draining reservations, never a mixed-version rollout.
- **Financial memory store:** completed keys expire on their next `TryBegin`. Capture includes empty 204 and pending pipe bytes; overflow fails closed. File contents are hashed. Process restart drops protection. Durable reconciliation and downstream business idempotency stay app-owned.

### Messaging and jobs

- **Job queue idempotency:** `IdempotencyKeyFor<TCommand>` requires storage record `IHasIdempotencyKey` (checked at `UseJobQueues`). Uniqueness is `(QueueID, IdempotencyKey)` until the row is purged, including completed rows. Providers throw `DuplicateJobException` with the existing `TrackingID`. The library does not catch raw DB unique violations. Null, empty, or whitespace selector results skip dedupe.
- **Event-bus hot path:** keep `_handlers` as `IEventHandler<TEvent>[]` for indexed/single-handler dispatch. Keep `Offload`, `OffloadOne`, `OffloadAll`, and `Filter` outside `Execute` to avoid per-publish display-class allocation. Single-handler `WaitForAny` uses `Task.WhenAny` so faults retain the mode’s uncaptured behavior.
- **Void command result:** keep public `Void` a zero-field struct with `Instance=default` so synchronous sends reuse the runtime’s cached `Task<Void>`. A class or extra field adds allocations. Audit `where TResult : class` on command/stream interfaces before changing it. Source: `Src/Messaging/Messaging.Core/Interfaces/ICommand.cs`; Library `Types.Void` means `typeof(void)`.
- **Job-queue AOT construction:** `UseJobQueues` uses `ActivatorUtilities.CreateInstance` and stores instances on `JobQueueBase.JobQueues`. Preserve that path; open-generic DI cannot close over value-type `Void` under Native AOT. Void jobs use class `JobQueueVoidResult`, with `ExecuteCommand` handling `ICommand` first. Keep that sentinel internal to queue construction: result-record/provider callbacks and failure-recovery lookup use public `Void`; result-type validation maps the sentinel back to `Void`. Source-generated result contexts need metadata for `Void`. `IJobTracker<>` remains open-generic because commands are classes.
- **Void command handler compatibility:** production no-result handlers may implement `ICommandHandler<TCommand>` or `ICommandHandler<TCommand, Void>`. Dispatch through the common two-argument interface; casting to the one-argument interface rejects valid discovered handlers. `CommandBusTests.Void_Command_Handler_Forms_Work_Through_Discovery` covers both forms with middleware and test-handler substitution.
- **Command middleware scope discovery:** discover middleware through the active request scope, even though executor singleton construction stays rooted. Cache only types; create instances per dispatch in the current scope. Constructor-injecting the enumerable resolves scoped middleware from the root and fails scope validation. Regression: `CommandBusScopedMiddlewareTests`.
- **Void command AOT execution:** `PrepareExecution` selects `VoidCommandHandlerExecutor<TCommand>` instead of closing `CommandHandlerExecutor<TCommand, Void>`. On dynamic-code platforms, resolve `IEnumerable<ICommandMiddleware<TCommand, Void>>` from DI so direct and helper registrations keep DI ordering. Under Native AOT, resolve middleware through `CommandMiddlewareRegistrations` and register closed `Register<TCommand, Void, TMiddleware>()`. Open registration throws for void commands without dynamic code. Propagate `NotSupportedException` rather than silently dropping the pipeline.
- **Lazy handler reflection:** keep `MakeGenericType` inside `CommandExtensions.HandlerInterfaceType`, invoked by `PrepareExecution` for first generic dispatch or `TestCommandHandlerMarker`. Hoisting it into every `ExecuteAsync` adds work and breaks AOT paths. Void test handlers use `ICommandHandler<TCommand>`; preserve `tHandlerOf1 is not null && tRes == Types.VoidResult`.
