# Messaging and Jobs

Remote event delivery and storage contracts: [remote-events.md](remote-events.md).

## Remote RPC and reflection

- **RPC wire format is per-connection and set-once:** set `RemoteConnection.MarshallerFactory` before any `Register<>()` (registration captures it and throws otherwise). Server and client must match. Both take the bound gRPC method name from the factory (MessagePack `""`, protobuf `Execute`). The default comes from DI, so `AddHandlerServer(marshaller:)` also becomes the default outbound factory in a process that is both server and client. Set it per connection when the peer uses a different format.
- **Reflection needs protobuf:** `MapHandlerReflection()` throws at startup unless `AddHandlerServer(marshaller: new ProtobufMarshallerFactory())` is set. `AddHandlerReflection()` only registers services. MessagePack has no descriptors. Attribute-free field numbers are positional, so adding or renaming a property renumbers the rest. Pin with `[ProtoContract]` / `[ProtoMember(n)]` when the contract must survive edits.
- **Reflection describes less than it serializes:** the descriptor generator skips `DateTime`, `DateOnly`, `TimeOnly`, `TimeSpan`, `decimal`, `Guid`, `Uri`, dictionaries, and nested commands (`CommandNotDescribable`). Those handlers still run via protobuf-net. Only field numbering is shared with the marshaller. `IsMessage(KeyValuePair<,>)` stays false so map entries are not published as empty messages.
- **Protobuf BCL denylist:** `ProtobufMarshallerFactory.IsMessage` / `IsNonMessageType` keep BCL specials out of attribute-free `Model.Add` (hollow contracts corrupt the wire). Edit that denylist together with the descriptor tests. Do not copy the type list into OKF.

## Messaging and jobs

### In-process event ownership and inheritance

- Both `AddFastEndpoints` and `AddMessaging` share `MessagingExtensions.RegisterHandlers`, which keeps mutable event builders local and returns an immutable `EventCatalog` snapshot. Standalone command/event discovery shares one provider-local `MessagingDiscovery`; resolving an exact bus must initialize discovery without requiring an earlier `UseMessaging` call.
- `EventRegistry` and `EventOptions` are provider-owned. Configure `UseMessaging(o => o.Events.EnableInheritance = true)` before mapping, job startup, publishing, or warmup. Do not move `ConfigureSerializerOnce` or introduce static event options. `MessagingOptions` is per startup call; its `Events` refers to the provider's persistent options. First publish/warmup atomically freezes the setting, including empty catalogs; a different later value throws.
- **Owner-approved registration constraint (2026-11-13):** event-handler registrations on a service collection must not change after its first provider is built. Registrations before or after either registration API are supported before that build. Multiple providers from an unchanged collection are supported. The lazy registration index publishes immutable metadata but relies on this constraint; it is not a provider-build snapshot. Index only unkeyed closed handler/enumerable contracts and the presence of open-generic handlers, never activate descriptor factories during indexing.
- Each singleton `EventBus<S>` owns a construction-time snapshot of the effective typed handler array for contract `S`, including caller-supplied arrays, and lazily publishes a thread-safe untyped subscription snapshot. Nonempty DI enumerable resolution replaces discovery for that contract; empty collections retain discovery. The registry reads exact buses through `IExactEventBus`, without publishing recursively or resolving the enumerable a second time. Only runtime-plan and discovered-instance lazy caches are needed in the registry; they prevent duplicate concurrent activation and remove failed entries conditionally for retries. Finish resolving the whole plan before delivery, offloading, or filtering.
- Discovered handlers use the owning provider's resolver. Built-in `CreateSingletonFromRoot` deliberately ignores another host's ambient request; retain the unit-test request-services exception and custom `IServiceResolver.CreateSingleton` integration. Reuse registered concrete instances. Container-owned DI handlers remain container-disposed.
- Enabled plans match assignable registered contracts, including variance, against the actual runtime type. Open-generic handlers add the actual base/interface hierarchy as finite candidates, with DI enforcing constraints. A generic handler can run for several closed contracts. Deduplicate discovery, not distinct DI entries or distinct handler interfaces on one class. Receivers record only at the publishing entry contract.
- Exact-interface invokers come from closed generic bus code, not expression interpretation or per-delivery reflection. A legacy nonempty direct constructor is local/exact-only and does not freeze host settings; null/empty constructors capture the active registry when available.
- **Event-bus hot path:** keep `_handlers` as `IEventHandler<TEvent>[]` for indexed/single-handler exact dispatch. `EventExecution` owns the shared wait-mode policy using static typed invocation strategies, without per-publish adapters. Keep offload closures outside `Execute` to avoid per-publish display-class allocation. Single-handler `WaitForAny` uses `Task.WhenAny` so faults retain the mode's uncaptured behavior.
- **Event filtering:** `EventHandlerFilter` shares type indexing and filtering between exact and inherited dispatch, evaluating the predicate once per implementation type per publish. Share decisions across that type's subscriptions, never across publishes. Exact buses and cached `EventDispatchPlan` instances own their subscriptions and first-handler indexes; decisions stay in bounded stack storage or a pooled buffer, so warmed identity filtering adds no allocations beyond dispatch and remains reentrant. Keep the typed exact path rather than converting handlers into per-publish adapters.
- Native AOT coverage includes `TestHarness/MessagingAotChecker` (Messaging + Generator, no Library), with fresh publication performed by `StandaloneMessagingTests`, plus opt-in HTTP fixtures alongside the default-off native event test. Class-event generic DI is supported; struct-event Native AOT remains outside scope. Keep discovery preservation and warmed allocation checks when changing the bridge.
- `IEvent` preserves implementing types' interface metadata for open-generic inheritance matching in Native AOT, including derived events. Do not rely on handler discovery alone: interfaces used only through runtime matching can otherwise be trimmed. Direct `EventBus<T>` models not implementing `IEvent` are outside this automatic preservation guarantee.

### Commands and jobs

- **Job queue idempotency:** `IdempotencyKeyFor<TCommand>` requires storage record `IHasIdempotencyKey` (checked at `UseJobQueues`). Uniqueness is `(QueueID, IdempotencyKey)` until the row is purged, including completed rows. Providers throw `DuplicateJobException` with the existing `TrackingID`. The library does not catch raw DB unique violations. Null, empty, or whitespace selector results skip dedupe.
- **Void command result:** keep public `Void` a zero-field struct with `Instance=default` so synchronous sends reuse the runtime’s cached `Task<Void>`. A class or extra field adds allocations. Audit `where TResult : class` on command/stream interfaces before changing it. Source: `Src/Messaging/Messaging.Core/Interfaces/ICommand.cs`; Library `Types.Void` means `typeof(void)`.
- **Job-queue AOT construction:** `UseJobQueues` uses `ActivatorUtilities.CreateInstance` and stores instances on `JobQueueBase.JobQueues`. Preserve that path; open-generic DI cannot close over value-type `Void` under Native AOT. Void jobs use class `JobQueueVoidResult`, with `ExecuteCommand` handling `ICommand` first. Keep that sentinel internal to queue construction: result-record/provider callbacks and failure-recovery lookup use public `Void`; result-type validation maps the sentinel back to `Void`. Source-generated result contexts need metadata for `Void`. `IJobTracker<>` remains open-generic because commands are classes.
- **Void command handler compatibility:** production no-result handlers may implement `ICommandHandler<TCommand>` or `ICommandHandler<TCommand, Void>`. Dispatch through the common two-argument interface; casting to the one-argument interface rejects valid discovered handlers. `CommandBusTests.Void_Command_Handler_Forms_Work_Through_Discovery` covers both forms with middleware and test-handler substitution.
- **Command middleware scope discovery:** discover middleware through the active request scope, even though executor singleton construction stays rooted. Cache only types; create instances per dispatch in the current scope. Constructor-injecting the enumerable resolves scoped middleware from the root and fails scope validation. Regression: `CommandBusScopedMiddlewareTests`.
- **Void command AOT execution:** `PrepareExecution` selects `VoidCommandHandlerExecutor<TCommand>` instead of closing `CommandHandlerExecutor<TCommand, Void>`. On dynamic-code platforms, resolve `IEnumerable<ICommandMiddleware<TCommand, Void>>` from DI so direct and helper registrations keep DI ordering. Under Native AOT, resolve middleware through `CommandMiddlewareRegistrations` and register closed `Register<TCommand, Void, TMiddleware>()`. Open registration throws for void commands without dynamic code. Propagate `NotSupportedException` rather than silently dropping the pipeline.
- **Lazy handler reflection:** keep `MakeGenericType` inside `CommandExtensions.HandlerInterfaceType`, invoked by `PrepareExecution` for first generic dispatch or `TestCommandHandlerMarker`. Hoisting it into every `ExecuteAsync` adds work and breaks AOT paths. Void test handlers use `ICommandHandler<TCommand>`; preserve `tHandlerOf1 is not null && tRes == Types.VoidResult`.
